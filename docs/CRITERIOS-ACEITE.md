# Critérios de aceite da apresentação visual

## Fundamentos
- [ ] `prototype/index.html` abre sem build nem serviços externos.
- [ ] CSS/JS próprios em arquivos separados; não há backend, API ou credenciais.
- [ ] As seis telas/áreas estão acessíveis por navegação clara.
- [ ] Sinalização discreta mas visível de demonstração com dados fictícios.
- [ ] Nenhum botão afirma ter enviado, assinado, sincronizado ou gerado um documento real.

## Fluxos
- [ ] Solicitação mostra dois serviços no mesmo pedido.
- [ ] Negociação precede o agendamento ilustrativo.
- [ ] Cliente/imóvel/solicitação/vistoria aparecem como conceitos distintos.
- [ ] Vistoria apresenta ambientes, categorias, checklist e constatações.
- [ ] Planta ilustrativa tem marcadores acionáveis e lista textual alternativa.
- [ ] Laudo de exemplo contém constatações, evidências ilustrativas e áreas reservadas de ART/assinatura.

## Visual e acessibilidade
- [ ] Verificado em 1440x900 e 390x844; sem rolagem horizontal.
- [ ] Contraste, foco de teclado, botões e labels adequados.
- [ ] A interface mobile tem alvos de toque confortáveis.
- [ ] Referência visual da engenharia respeitada; sem cópias literais da imagem ou SIAPP.
- [ ] Cor de destaque #FF2C23 empregada com bom contraste.
- [ ] Estados interativos coerentes (abas, menu, modal, seleção).

## Entrega
- [ ] README explica como abrir e limitações.
- [ ] Checklist de validação preenchido pelo operador.
- [ ] Codex reporta arquivos modificados, como testar, limitações e capturas se disponíveis.
- [ ] Nenhuma implementação da V1 foi iniciada por engano.
